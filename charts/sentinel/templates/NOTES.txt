Sentinel is running in observe mode: it reads, reports and records, and changes nothing.

Watched namespaces: {{ join ", " .Values.watch.namespaces }}

See what Sentinel can see and do on this cluster, as its own identity:

  sentinel capabilities --namespaces {{ join "," .Values.watch.namespaces }} \
    --agent-namespace {{ .Release.Namespace }} \
    --as system:serviceaccount:{{ .Release.Namespace }}:sentinel

The controller also records every change in its capability report in the Ledger:

  kubectl -n {{ .Release.Namespace }} logs deploy/sentinel | grep "capability report"

Install the sentinel-fence chart (as a cluster admin) to bound what Sentinel itself may change.
{{- if .Values.lab.enabled }}
The Lab acts only once the fence knows its pool:

  helm upgrade --install sentinel-fence charts/sentinel-fence --reuse-values \
    --set lab.namespace={{ .Release.Namespace }} --set 'lab.pool={{ "{" }}{{ join "," (include "sentinel.labNamespaces" . | fromJsonArray) }}{{ "}" }}'
{{- end }}
{{- if .Values.nodeAgent.enabled }}

The tier-1 node agent is on: a DaemonSet on every node tails /var/log/pods
(and cgroup v2) through read-only hostPaths, redacts on the node, and posts
to the controller on port 4319. It needs root without capabilities; clusters
that cannot run that shape (Fargate and similar) keep it off.
{{- else }}

The tier-1 node agent is off. Turn it on with --set nodeAgent.enabled=true
where nodes can run a root DaemonSet with read-only hostPaths.
{{- end }}
