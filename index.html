What is Sentinel?

Sentinel plugs into any Kubernetes cluster, watches for incidents, diagnoses them with an LLM, writes fixes, tests them in a sandbox, and opens Pull Requests — all on its own.

When a pod goes into CrashLoopBackOff, Sentinel doesn't just alert you. It:

  1. Fetches the real pod logs from the crashing container
  2. Clones your repo and searches the source code for the bug (same pattern as SWE-agent / OpenHands)
  3. Diagnoses the root cause with a 4-agent LLM pipeline (Investigator → Evidence Gatherer → Analyst → Fix Proposer)
  4. Writes a patch — the actual file changes, not a recommendation
  5. Builds a canary image with Kaniko and tests it in a sandbox namespace
  6. Opens a PR with a sandbox-verified label — ready for you to merge

All in ~4 minutes. While you sleep.

6

Kaniko build + 3-level sandbox + PR

The agent loop (what makes it accurate)

Sentinel doesn't guess which files to look at. It does what real coding agents do:

1. Clone the repo locally (go-git, ~2 seconds)
2. Walk the file tree (filtered: no node_modules, vendor, .git)
3. LLM Round 1: "what should I search for?"
   → emits 3-8 search queries: ["DB_PASSWORD", "KeyError", "def main"]
4. Run the searches locally (Go regexp)
   → instant, no API calls, no rate limits
5. LLM Round 2: "given these results, what's the root cause?"
   → returns hypotheses + files to read
6. Read those files from disk (zero API calls)
7. Pass source to Fix Proposer → writes the patch
8. Open PR with sandbox-verified label

Same pattern as SWE-agent, OpenHands, and Aider. Works for any repo, any language, any layout — because the LLM searches by content, not by filename.

Install in 60 seconds

helm repo add sentinel https://karimzakzoukz.github.io/sentinel/
helm repo update

helm install sentinel sentinel/sentinel --version 3.0.2 \
  --namespace sentinel --create-namespace \
  --set sentinel.githubToken=YOUR_GITHUB_TOKEN \
  --set sentinel.llm.apiKey=YOUR_LLM_API_KEY \
  --set sentinel.llm.provider=gemini \
  --set 'sentinel.rbac.writeNamespaces={sim}'

kubectl -n sentinel get pods -w
# sentinel-xxx   1/1 Running   0   1s

Trigger an incident

cat <<EOF | kubectl apply -f -
apiVersion: sentinel.io/v1alpha1
kind: SentinelIncident
metadata:
  name: test-crashloop
  namespace: sim
spec:
  service: my-app
  namespace: sim
  reason: CrashLoopBackOff detected on my-app
  trigger: manual
  repo: myorg/my-app
EOF

kubectl -n sentinel logs -f deploy/sentinel

Watch Sentinel clone your repo, search the source, diagnose the bug, build a canary image, verify it in a sandbox, and open a PR — all autonomously.
